# Оценка повреждений подержанных автомобилей Car_dem

## Назначение приложения

Приложение предназначено для оценки состояния подержанного автомобиля по фотографиям. Пользователь загружает фотографии машины и указывает её марку, модель и год выпуска. В ответ он получает список найденных повреждений: тип повреждения (скол, вмятина, царапина, трещина) и степень тяжести (лёгкая, средняя, сильная). Место повреждения показывается прямо на фотографии цветной рамкой, цвет рамки соответствует типу повреждения. Результат сохраняется как отчёт — оценка (Assessment).

В дальнейшем предполагается, что повреждения будет находить обученная модель компьютерного зрения. 

В приложении есть две роли:

- **Пользователь** — создаёт оценки и видит только свои.
- **Администратор** — видит оценки всех пользователей.

## Основные пользовательские сценарии

1. Пользователь входит в систему или регистрируется, если аккаунта ещё нет.
2. На главной странице он видит список своих оценок в виде карточек: фотография автомобиля, марка и модель, год, дата создания и количество найденных повреждений.
3. Пользователь нажимает «Создать оценку», заполняет данные автомобиля, выбирает фотографии и видит их превью до отправки.
4. После создания открывается страница оценки, где можно посмотреть фотографии и список повреждений, а также добавить или удалить повреждение вручную.
5. Администратор открывает отдельный раздел и видит таблицу оценок всех пользователей, может открыть любую из них.

## Экраны приложения

Переходы между экранами сделаны через клиентскую маршрутизацию (react-router-dom), страница при этом не перезагружается.

- **/login** — вход в систему. Форма с email и паролем, проверяются заполненность полей и формат email.
- **/register** — регистрация. Форма с именем, email и паролем.
- **/dashboard** — список оценок текущего пользователя и кнопка «Создать оценку».
- **/assessments/new** — форма создания оценки: марка, модель, год выпуска и загрузка фотографий с превью.
- **/assessments/:id** — подробная информация об оценке: фотографии, список повреждений, форма добавления нового повреждения и кнопка удаления у каждого.
- **/admin** — таблица всех оценок с указанием владельца.

Экраны входа и регистрации показываются без меню. На остальных экранах сверху есть общая шапка с навигацией: «Мои оценки», «Новая оценка», «Админ» и кнопка «Выйти».

## Технологии

- React 19 и TypeScript
- Vite — сборка и запуск в режиме разработки
- react-router-dom — маршрутизация между экранами
- Mantine — библиотека готовых UI-компонентов
- ESLint — проверка кода

Библиотека Mantine выбрана потому, что у неё простой и понятный набор компонентов (карточки, кнопки, поля ввода, выпадающие списки, таблицы, бейджи) и аккуратный внешний вид без дополнительной настройки. За счёт этого все экраны оформлены одинаково, текст читаемый, а страницы подстраиваются под ширину окна: сетка карточек на главной перестраивается с трёх колонок в одну на узком экране.

## Структура проекта

Весь код приложения находится в папке src.

- **main.tsx** — точка входа. Здесь приложение подключается к странице и оборачивается в MantineProvider (стили и тема) и BrowserRouter (маршрутизация).
- **App.tsx** — список всех маршрутов приложения.
- **types.ts** — типы данных: Car (автомобиль), Damage (повреждение), Assessment (оценка), User (пользователь), а также допустимые значения типа и степени тяжести повреждения. У повреждения, найденного моделью, есть фотография и рамка (box) в долях от размера фото.
- **index.css** —  файл со стилями, основное оформление берётся из Mantine.
- **data/mockData.ts** — демонстрационные данные (пользователи и оценки) и функции для работы с ними: получить оценки пользователя, найти оценку по id, получить имя владельца, добавить новую оценку.
- **components/** — небольшие компоненты, которые используются на разных страницах: Layout.tsx (шапка с меню и общая разметка), AssessmentCard.tsx (карточка оценки на главной), DamageItem.tsx (одно повреждение в списке с кнопкой удаления), PhotoWithBoxes.tsx (фотография с рамками повреждений).
- **pages/** — страницы приложения, по одной на каждый экран: LoginPage.tsx, RegisterPage.tsx, DashboardPage.tsx, NewAssessmentPage.tsx, AssessmentDetailsPage.tsx, AdminPage.tsx.

Фотографии автомобилей для демонстрационных данных лежат в папке public/cars.

## Демонстрационные данные

Frontend пока не подключён к backend, поэтому все данные находятся в файле data/mockData.ts. Текущим пользователем считается пользователь с id 1, ему принадлежат четыре оценки — они и показываются на главной странице. В разделе администратора выводятся все восемь.

Новая оценка, созданная через форму, добавляется в этот же список и видна на главной странице, но только до перезагрузки страницы, так как сохранять данные пока некуда. Повреждения, добавленные вручную на странице оценки, тоже хранятся только в состоянии этой страницы.

## Изменения интерфейса

При работе над backend из повреждения убрано поле «Место на кузове» (бампер, дверь, капот и т. д.). Модель компьютерного зрения находит на фото только рамку и тип повреждения, поэтому надёжно определить деталь кузова она не может. Вместо этого место повреждения показывается рамкой на фотографии, а цвет рамки объясняется легендой над фотографиями. Скриншоты экрана оценки пока не обновлены.

## Backend

Backend написан на Python с использованием FastAPI, данные хранятся в PostgreSQL и обрабатываются через SQLAlchemy. Код находится в папке backend.

### Структура backend

- **app/main.py** — создание приложения, подключение маршрутов и папки с загруженными фото, создание таблиц при запуске.
- **app/config.py** — настройки приложения, читаются из файла .env.
- **app/database.py** — подключение к PostgreSQL и сессии БД.
- **app/models.py** — модели SQLAlchemy.
- **app/schemas.py** — схемы валидации запросов и ответов (Pydantic).
- **app/crud.py** — операции с данными и бизнес-логика.
- **app/detector.py** — поиск повреждений на фото с помощью модели компьютерного зрения.
- **app/routers/** — маршруты API: users.py, assessments.py, damages.py.
- **app/seed.py** — скрипт, который добавляет начальных пользователей.
- **uploads/** — загруженные фотографии (не попадает в репозиторий).

### Модель данных

- **users** — пользователи: id, name, email (уникальный), password.
- **assessments** — оценки: id, brand, model, year, created_at, user_id (внешний ключ на users).
- **photos** — фотографии оценки: id, filename, assessment_id (внешний ключ на assessments).
- **damages** — повреждения: id, type, severity, comment, assessment_id (внешний ключ на assessments), photo_id (необязательный внешний ключ на photos), x, y, width, height (рамка повреждения в долях от размера фото, необязательные, у добавленных вручную повреждений пустые).

Связи: у пользователя много оценок, у оценки много фотографий и много повреждений, повреждение может относиться к одной фотографии. При удалении пользователя удаляются его оценки, а при удалении оценки — её фотографии (и файлы на диске) и повреждения.

Пароли пока хранятся в открытом виде, хеширование будет добавлено вместе с авторизацией.

### Модель компьютерного зрения

При создании оценки каждая загруженная фотография проходит через готовую модель YOLO [shawnmichael/yolo-car-damage-detection](https://huggingface.co/shawnmichael/yolo-car-damage-detection), обученную на датасете CarDD. Модель скачивается с Hugging Face при первой загрузке фото (нужен интернет), поэтому первый запрос выполняется дольше.

Для каждой найденной рамки создаётся повреждение:

- тип: dent — «Вмятина», scratch — «Царапина», crack — «Трещина», glass shatter — «Скол»; остальные классы модели (разбитая фара, спущенное колесо) пропускаются;
- степень тяжести определяется по площади рамки: меньше 1% кадра — «Лёгкая», меньше 5% — «Средняя», иначе «Сильная»;
- в комментарий записывается уверенность модели.

Это учебный проект, поэтому точность модели невысокая: она может ничего не найти или ошибиться, тогда повреждения можно добавить и удалить вручную.

### Настройка и запуск backend

Нужны Python 3.10–3.13 (для библиотеки torch) и установленный PostgreSQL.

1. Создать базу данных: `CREATE DATABASE car_dem;`
2. Перейти в папку backend и создать виртуальное окружение:

```
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

3. Скопировать .env.example в .env и указать в нём пользователя и пароль PostgreSQL.
4. Создать таблицы и добавить начальных пользователей (таблицы также создаются автоматически при запуске сервера):

```
python -m app.seed
```

5. Запустить сервер:

```
uvicorn app.main:app --reload
```

Сервер будет доступен по адресу `http://127.0.0.1:8000`, а интерактивная документация API со всеми запросами — по адресу `http://127.0.0.1:8000/docs`.

### Основные запросы API

- `POST /users`, `GET /users`, `GET /users/{id}`, `PUT /users/{id}`, `DELETE /users/{id}` — пользователи.
- `POST /assessments` (форма с полями brand, model, year, user_id и файлами photos), `GET /assessments` (необязательный параметр user_id), `GET /assessments/{id}`, `PUT /assessments/{id}`, `DELETE /assessments/{id}` — оценки.
- `POST /assessments/{id}/damages`, `GET /assessments/{id}/damages`, `GET /damages/{id}`, `PUT /damages/{id}`, `DELETE /damages/{id}` — повреждения.
- `GET /uploads/{filename}` — загруженная фотография.

Ошибки возвращаются с понятным сообщением: 404 — запись не найдена, 409 — email уже занят, 400 — загружен не файл изображения, 422 — некорректные данные (например, год вне диапазона 1950–2026).

Параметр user_id при создании оценки временный: пока нет авторизации, владелец указывается явно.
