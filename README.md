# Оценка повреждений подержанных автомобилей Car_dem

## Назначение приложения

Приложение предназначено для оценки состояния подержанного автомобиля по фотографиям. Пользователь загружает фотографии машины и указывает её марку, модель и год выпуска. В ответ он получает список найденных повреждений: тип повреждения (скол, вмятина, царапина, трещина) и степень тяжести (лёгкая, средняя, сильная). Место повреждения показывается прямо на фотографии цветной рамкой, цвет рамки соответствует типу повреждения. Результат сохраняется как отчёт — оценка (Assessment).

В дальнейшем предполагается, что повреждения будет находить обученная модель компьютерного зрения. 

В приложении есть две роли:

- **Пользователь** — создаёт оценки и видит только свои.
- **Администратор** — видит оценки всех пользователей.

## Основные пользовательские сценарии

1. Пользователь входит в систему или регистрируется, если аккаунта ещё нет.
2. На главной странице он видит список своих оценок в виде карточек: фотография автомобиля, марка и модель, год, дата создания и количество найденных повреждений.
3. Пользователь нажимает «Создать оценку», заполняет данные автомобиля, выбирает фотографии и видит их превью до отправки.
4. После создания открывается страница оценки, где можно посмотреть фотографии и список повреждений, а также добавить или удалить повреждение вручную.
5. Администратор открывает отдельный раздел и видит таблицу оценок всех пользователей, может открыть любую из них.

## Экраны приложения

Переходы между экранами сделаны через клиентскую маршрутизацию (react-router-dom), страница при этом не перезагружается.

- **/login** — вход в систему. Форма с email и паролем, проверяются заполненность полей и формат email.
- **/register** — регистрация. Форма с именем, email и паролем.
- **/dashboard** — список оценок текущего пользователя и кнопка «Создать оценку».
- **/assessments/new** — форма создания оценки: марка, модель, год выпуска и загрузка фотографий с превью.
- **/assessments/:id** — подробная информация об оценке: фотографии, список повреждений, форма добавления нового повреждения и кнопка удаления у каждого.
- **/admin** — таблица всех оценок с указанием владельца.

Экраны входа и регистрации показываются без меню. На остальных экранах сверху есть общая шапка с навигацией: «Мои оценки», «Новая оценка», «Админ» и кнопка «Выйти».

## Технологии

- React 19 и TypeScript
- Vite — сборка и запуск в режиме разработки
- react-router-dom — маршрутизация между экранами
- Mantine — библиотека готовых UI-компонентов
- ESLint — проверка кода

Библиотека Mantine выбрана потому, что у неё простой и понятный набор компонентов (карточки, кнопки, поля ввода, выпадающие списки, таблицы, бейджи) и аккуратный внешний вид без дополнительной настройки. За счёт этого все экраны оформлены одинаково, текст читаемый, а страницы подстраиваются под ширину окна: сетка карточек на главной перестраивается с трёх колонок в одну на узком экране.

## Структура проекта

Весь код frontend находится в папке src. Структура сделана упрощённо по мотивам Feature-Sliced Design: код разделён на слои, и каждый слой может использовать только слои ниже себя (app → pages → widgets → features → entities → shared).

- **app/** — настройка приложения. main.tsx — точка входа, приложение оборачивается в MantineProvider (стили и тема), BrowserRouter (маршрутизация) и AuthProvider (состояние пользователя); App.tsx — список всех маршрутов; ProtectedRoute.tsx — защита страниц: неавторизованного пользователя отправляет на страницу входа, а для страниц с adminOnly (раздел «Админ») ещё и проверяет роль администратора.
- **pages/** — страницы, по одной папке на каждый экран: login, register, dashboard, new-assessment, assessment-details (страница загружает оценку, а AssessmentDetails.tsx показывает её), admin. Страница собирает экран из готовых частей и отвечает за загрузку данных.
- **widgets/** — крупные самостоятельные блоки интерфейса: layout — Layout (шапка с меню и место для текущей страницы).
- **features/** — пользовательские действия: login (форма входа), register (форма регистрации), auth (состояние авторизации: AuthProvider и хук useAuth), create-assessment (форма создания оценки с превью фото), add-damage (раскрывающаяся форма добавления повреждения), delete-damage (кнопка удаления повреждения). Формы проверяют ввод и показывают ошибки под полями.
- **entities/** — сущности предметной области. В папке model лежат типы, константы и демонстрационные данные, в папке ui — компоненты сущности.
  - assessment — оценка и автомобиль: типы, данные и функции для работы с ними, карточка AssessmentCard;
  - damage — повреждение: типы, типы и степени тяжести с цветами, DamageItem (одно повреждение), DamageCountBadge (счётчик повреждений), PhotoWithBoxes (фото с рамками);
  - user — пользователь: тип, список пользователей, текущий пользователь; в папке api — запросы авторизации (регистрация, вход, текущий пользователь, выход).
- **shared/** — общий код без привязки к предметной области: api — клиент для запросов к backend (client.ts) и работа с токенами в localStorage (tokens.ts); ui — LoadingState, ErrorState, EmptyState; lib — validation (проверка обязательных полей и email), formatDate (формат даты), useAsyncData (загрузка данных с состояниями загрузки и ошибки).
- **index.css** — небольшой файл со стилями анимации, основное оформление берётся из Mantine.

В public/cars лежат примеры фотографий для загрузки. Оценки и повреждения загружаются с сервера, демонстрационных списков на frontend больше нет.

## Динамический интерфейс

- **Формы и валидация.** Формы входа, регистрации, создания оценки и добавления повреждения проверяют данные до отправки: обязательные поля, формат email, длину пароля (от 6 символов), год выпуска (от 1950 до 2026), длину комментария (до 300 символов). Ошибки показываются под соответствующими полями.
- **Состояния данных.** Списки оценок (главная и раздел администратора) и страница оценки показывают индикатор загрузки, сообщение об ошибке с кнопкой «Повторить» и сообщение о том, что данных нет. Эти состояния связаны с реальными запросами к API. Например, при открытии несуществующей оценки сервер возвращает 404, а интерфейс показывает сообщение «Оценка не найдена».
- **Анимации.** Страницы, карточки оценок и повреждения плавно появляются, карточка оценки приподнимается при наведении, форма добавления повреждения раскрывается по кнопке «Открыть форму».
- **Типизация.** Типы данных описаны в entities/*/model/types.ts, у всех компонентов описаны типы свойств, в обработчиках событий используются типы React.

## Интеграция frontend и backend (лабораторная работа №5)

Основные экраны работают с FastAPI и PostgreSQL. На главной странице показываются оценки вошедшего пользователя, в разделе администратора — все оценки с именами владельцев. Файлы запросов находятся в entities/assessment/api и entities/damage/api. Ответ API преобразуется в тип Assessment: поля автомобиля собираются в car, пути фотографий дополняются адресом backend, рамки повреждений связываются с фотографиями по photo_id.

Через интерфейс можно:

- создать оценку и загрузить фотографии (FormData);
- открыть оценку и увидеть найденные моделью повреждения;
- изменить марку, модель и год своей оценки;
- удалить свою оценку вместе с фотографиями и повреждениями после подтверждения;
- добавить, изменить и удалить повреждение своей оценки.

Изменения отправляются на сервер, затем оценка загружается заново. После перезагрузки страницы данные сохраняются. Администратор может просматривать чужие оценки, но кнопки изменения и удаления для них скрыты. Сервер также проверяет права независимо от интерфейса.

Во время отправки кнопки показывают загрузку. Ошибки сети, валидации и доступа выводятся в интерфейсе. Если access token истёк, клиент обновляет его через refresh token и повторяет запрос один раз. Если обновить сессию нельзя, пользователь возвращается на страницу входа.

### Проверка приложения

1. Запустить PostgreSQL, backend и frontend по инструкциям ниже.
2. Зарегистрироваться, войти и убедиться, что новый пользователь видит пустой список.
3. Создать оценку с фотографией, открыть результат и проверить рамки на фото.
4. Изменить автомобиль, добавить и изменить повреждение. Перезагрузить страницу и проверить сохранение.
5. Удалить повреждение, затем удалить оценку с подтверждением. Проверить пустой список.
6. Войти администратором: открыть список всех оценок и чужую оценку. Кнопок изменения чужих данных быть не должно.
7. Открыть несуществующую оценку, проверить сообщение об ошибке и возврат к списку. Остановить backend и проверить сообщение об отсутствии связи.
8. Выйти и проверить, что защищённые страницы больше не открываются.

Проверено с локальной PostgreSQL: регистрация, вход и выход, загрузка фотографии и обработка моделью, CRUD оценок и повреждений, сохранение после перезагрузки, просмотр администратором. Отдельно проверены ответы 401, 403 и 422, обновление access token и отказ после отзыва refresh token. Проверки frontend: `npm run build`, `npm run lint`.

## Backend

Backend написан на Python с использованием FastAPI, данные хранятся в PostgreSQL и обрабатываются через SQLAlchemy. Код находится в папке backend.

### Структура backend

- **app/main.py** — создание приложения, подключение маршрутов, CORS для frontend и папки с загруженными фото, создание таблиц при запуске.
- **app/config.py** — настройки приложения (в том числе секретный ключ и сроки жизни токенов), читаются из файла .env.
- **app/security.py** — хеширование паролей (bcrypt) и создание токенов.
- **app/dependencies.py** — проверка access token (получение текущего пользователя), проверка роли администратора и проверка, что оценка принадлежит пользователю.
- **app/database.py** — подключение к PostgreSQL и сессии БД.
- **app/models.py** — модели SQLAlchemy.
- **app/schemas/** — схемы валидации (Pydantic): input.py — данные, которые присылает клиент (UserCreate, LoginRequest, RefreshRequest, DamageCreate, AssessmentUpdate), output.py — данные, которые отдаёт сервер (UserOut, TokenOut, AccessTokenOut, DamageOut, PhotoOut, AssessmentOut).
- **app/crud.py** — операции с данными и бизнес-логика.
- **app/detector.py** — поиск повреждений на фото с помощью модели компьютерного зрения.
- **weights/** — файл готовой обученной модели.
- **app/routers/** — маршруты API: auth.py, users.py, assessments.py, damages.py.
- **app/seed.py** — скрипт, который добавляет начальных пользователей.
- **uploads/** — загруженные фотографии (не попадает в репозиторий).

### Модель данных

- **users** — пользователи: id, name, email (уникальный), password_hash (bcrypt-хеш пароля), is_admin (роль администратора, по умолчанию false).
- **refresh_tokens** — refresh token пользователей: id, token_hash (SHA-256 от токена), expires_at, revoked, user_id (внешний ключ на users).
- **assessments** — оценки: id, brand, model, year, created_at, user_id (внешний ключ на users).
- **photos** — фотографии оценки: id, filename, assessment_id (внешний ключ на assessments).
- **damages** — повреждения: id, type, severity, comment, assessment_id (внешний ключ на assessments), photo_id (необязательный внешний ключ на photos), x, y, width, height (рамка повреждения в долях от размера фото, необязательные, у добавленных вручную повреждений пустые).

Связи: у пользователя много оценок, у оценки много фотографий и много повреждений, повреждение может относиться к одной фотографии. При удалении пользователя удаляются его оценки, а при удалении оценки — её фотографии (и файлы на диске) и повреждения.

### Модель компьютерного зрения

При создании оценки каждая загруженная фотография проходит через готовую модель YOLO [shawnmichael/yolo-car-damage-detection](https://huggingface.co/shawnmichael/yolo-car-damage-detection), обученную на датасете CarDD. Файл модели (около 6 МБ, лицензия Apache 2.0) лежит в репозитории в папке backend/weights, поэтому интернет для работы не нужен. Модель загружается при первой загрузке фото, поэтому первый запрос выполняется чуть дольше. Сервер нужно запускать из папки backend, чтобы путь weights/best_dts.pt находился.

Для каждой найденной рамки создаётся повреждение:

- тип: dent — «Вмятина», scratch — «Царапина», crack — «Трещина», glass shatter — «Скол»; остальные классы модели (разбитая фара, спущенное колесо) пропускаются;
- степень тяжести определяется по площади рамки: меньше 1% кадра — «Лёгкая», меньше 5% — «Средняя», иначе «Сильная»;
- в комментарий записывается уверенность модели.

Это учебный проект, поэтому точность модели невысокая: она может ничего не найти или ошибиться, тогда повреждения можно добавить, изменить и удалить вручную.

### Настройка и запуск backend

Нужны Python 3.10–3.13 (для библиотеки torch) и установленный PostgreSQL.

1. Создать базу данных: `CREATE DATABASE car_dem;`
2. Перейти в папку backend и создать виртуальное окружение:

```
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

3. Скопировать .env.example в .env, указать в нём пользователя и пароль PostgreSQL и задать SECRET_KEY — длинную случайную строку для подписи токенов. Получить её можно так: `python -c "import secrets; print(secrets.token_hex(32))"`.
4. Создать таблицы и добавить начальных пользователей (таблицы также создаются автоматически при запуске сервера):

Если таблица users была создана до появления авторизации (со столбцом password), её нужно пересоздать или переименовать столбец в password_hash и заменить пароли хешами: автоматически таблицы не изменяются. Сделать администратором существующего пользователя можно командой `UPDATE users SET is_admin = TRUE WHERE email = '...';`.

### Аутентификация и авторизация

- **Регистрация и вход.** Пароль при регистрации хешируется алгоритмом bcrypt (с солью), в БД хранится только хеш. При входе по email и паролю сервер возвращает два токена.
- **Access token** — JWT, подписанный секретным ключом (HS256), в нём лежит id пользователя. Срок действия — 15 минут (ACCESS_TOKEN_MINUTES). Передаётся в заголовке `Authorization: Bearer <токен>`.
- **Refresh token** — случайная строка, нужна только для получения нового access token. Срок действия — 7 дней (REFRESH_TOKEN_DAYS). В БД хранится не сам токен, а его хеш, а также срок действия и признак «отозван».
- **Обновление.** `POST /auth/refresh` по действующему refresh token выдаёт новый access token. Если токен не найден, отозван или истёк, сервер отвечает 401. Frontend делает это автоматически: если запрос завершился ошибкой 401, он один раз обновляет access token и повторяет запрос.
- **Защита маршрутов.** Публичные маршруты — регистрация, вход, обновление токена и выход. Остальные требуют access token: без него или с неверным/истёкшим токеном сервер отвечает 401. Оценки и повреждения принадлежат пользователю: он видит только свои, а при обращении к чужой оценке, повреждению или профилю сервер отвечает 403. Владелец новой оценки определяется по токену.
- **Администратор.** У пользователя есть поле is_admin. Администратор может только смотреть: список всех пользователей (`GET /users`), все оценки (`GET /assessments/all`), а также любую оценку и её повреждения по id. Изменять и удалять чужие данные ему нельзя (403). Остальным пользователям админские маршруты отвечают 403. Администратора назначают вручную в БД или через seed.py.
- **Выход.** `POST /auth/logout` отзывает refresh token текущей сессии, после этого обновить access token с его помощью нельзя. Frontend при выходе удаляет токены из localStorage и очищает состояние пользователя.

Токены на frontend хранятся в localStorage — это простой вариант для учебного проекта. Его недостаток в том, что токены доступны скриптам страницы (при XSS-атаке их можно украсть); в промышленных проектах refresh token часто хранят в httpOnly cookie. Фотографии по адресу /uploads отдаются без авторизации, но имена файлов случайные.

### Основные запросы API

- `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`, `GET /auth/me` — регистрация, вход, обновление access token, выход и текущий пользователь.
- `GET /users` — список пользователей (только администратор).
- `GET /users/{id}`, `PUT /users/{id}`, `DELETE /users/{id}` — свой профиль (доступны только для текущего пользователя).
- `POST /assessments` (форма с полями brand, model, year и файлами photos), `GET /assessments` (оценки текущего пользователя), `GET /assessments/all` (все оценки, только администратор), `GET /assessments/{id}` (администратор может смотреть и чужие), `PUT /assessments/{id}`, `DELETE /assessments/{id}` — оценки.
- `POST /assessments/{id}/damages`, `GET /assessments/{id}/damages`, `GET /damages/{id}`, `PUT /damages/{id}`, `DELETE /damages/{id}` — повреждения.
- `GET /uploads/{filename}` — загруженная фотография.

Все маршруты, кроме `/auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout` и `/uploads`, требуют access token.

Ошибки возвращаются с понятным сообщением: 401 — нет токена, токен неверный или истёк, неверный email или пароль; 403 — нет прав на чужую запись или на админские маршруты; 404 — запись не найдена, 409 — email уже занят, 400 — загружен не файл изображения, 422 — некорректные данные (например, год вне диапазона 1950–2026).
